# 139. Аудит сайта: стенд, автопроверки, исправления (ноябрь 2026)

Раздел для `PROJECT_5.md`. Описывает, как устроена проверка всего сайта по ролям, дизайнам и размерам
экрана, что было найдено и исправлено. Подробный список ошибок — `docs/audit/BUGS.md`, карта сайта и
матрица проверки — `docs/audit/PHASE0.md`.

## 139.1 Стенд

- Эмуляторы Firebase: Firestore, Auth, Storage и Functions (облачные функции работают, кроме функций
  по расписанию: для них нужен pubsub).
  Запуск из корня:
  `npm ci --prefix functions` (один раз), затем
  `env -u HTTPS_PROXY -u https_proxy npx --prefix tests firebase emulators:start --only firestore,auth,storage,functions --project mirflowersbase`.
  Без `env -u …` функции не запускаются за прокси.
- Тестовая база: `node tests/seed.cjs`. Создаёт 10 сотрудников всех ролей (пароль у всех `secret12`), две
  точки, 300 заказов во всех статусах (с запросами отмены и скидки, переделками, доставкой), 80 позиций
  склада с партиями, 15 букетов (один — сладкий бокс), 60 чатов с фото, голосовыми и цитатами,
  сообщения команды, смены, расходы, отчёты. Специально добавлены плохие данные: пустые поля, `<script>`
  в тексте, очень длинные строки.
- Сайт берётся готовым из корня (после `node build/build.mjs`) и раздаётся с флагами `__EMU`
  (`tests/audit-lib.cjs`, порт 5079). В боевой сборке флагов нет — сайт работает с настоящей базой.
- **Журнал эмулятора** `firestore-debug.log` за долгий прогон вырастает до нескольких гигабайт, после
  этого эмулятор начинает сбоить («Transaction lock timeout», «Event loop shut down»), вход на сайте
  падает с «Нет интернета», а Firestore — с внутренней ошибкой. Перед большим прогоном остановите
  эмуляторы, удалите журнал, запустите заново и перезалейте базу.

## 139.2 Автопроверки (`tests/`)

| Файл | Что делает |
|---|---|
| `audit-lib.cjs` | Стенд, вход под ролью, размер экрана, тема, язык, дизайн |
| `sitemap.cjs` | Карта: какие разделы видит каждая роль → `tests/out/audit/sitemap.json` |
| `audit-walk.cjs` | Обход: роль × раздел (+ подразделы настроек и склада) × размер × дизайн × тема × язык |
| `audit-flow.cjs` | Сквозные сценарии с проверкой данных в базе |

`audit-walk.cjs` на каждом экране проверяет: ошибки JS, горизонтальную прокрутку, блоки за краем экрана,
кнопки меньше 32 px (с учётом расширенной зоны нажатия `::after` и чекбоксов внутри подписи), кнопки,
перекрытые другим блоком (кроме свёрнутых `<details>` и липких шапок), кнопки за краем ряда без
видимой прокрутки (только мышь), пустой экран, `undefined`/`NaN`/`Invalid Date` в тексте, `<script>` в
разметке, контраст текста. В казахском языке он дополнительно ищет русские слова без перевода
(принятые заимствования «Заказдар», «Клиенттер», «Склад», «Доставка» ошибкой не считаются).
Запуск: `node tests/audit-walk.cjs "Dark Elegance" owner,operator phone,laptop dark kk`.

`audit-flow.cjs` проходит: оператор создаёт заказ (двойное нажатие даёт один заказ) → флорист
«Начать сборку» → «Готов» с фото → приёмка → оплата («Принять без чека») → выдача; затем журнал,
ссылку клиенту (`pubOrders`), доставку (заказ выставляется курьерам сам после приёмки; курьер
берёт → «Забрал, еду» → «Доставлено» с фото), отмену оператором через запрос и разрешение админа,
права помощника и `status.html`. Имя клиента тест вводит как человек: нажимает на поле и печатает.

## 139.3 Что исправлено

- Обработчик «Кассы» ловил служебную метку `data-kb`, которая стоит на всех полях ввода, поэтому клик
  по любому полю у менеджера открывал продажу. У «Кассы» теперь своя метка `data-kbq`.
- Имя клиента, подставленное по телефону, склеивалось с набранным. Теперь его подставляет
  `autoName(input, value)`: ставит метку `data-auto` и выделяет текст, если поле в фокусе. Набранный
  текст заменяет подставленное имя, первое ручное изменение снимает метку.
  Подставляется в трёх местах: по телефону (событие `change`), подсказка `clHint` и имя компании.
- «Ссылка клиенту» дочитывает заказ из базы, если его нет в текущем списке (выданный, другой день).
- `fsDead`: если внутренний сбой Firestore повторился меньше чем через минуту после автоперезагрузки,
  сайт перезагружается ещё раз, когда минута пройдёт, а не остаётся без живых обновлений.
- На компьютере (`pointer:fine`) ряд фильтров чатов переносится на новую строку.
- В тёмной теме текст счётчиков `.nb` тёмный: фон `--bad` там светлый.
- Зона нажатия `.hint-btn`, `.jrx` и ссылок «удалить» увеличена через `::after` при прежнем виде.
- Казахский: добавлены переводы подсказок настроек, команды, чатов, закупки и премии, кнопки в кавычках
  внутри казахских фраз теперь называются так же, как сами кнопки («Өзгерту», «Сақтау», «Қабылдау»).
- Bloom: акцент #c9416a вместо #ef7a9a (розовый текст на белом читался плохо), кнопки темнее. Neon Flowers и
  Soft Dream: тёмный текст на акцентных кнопках (`--on`), в Soft Dream темнее второстепенный текст (`--mut`).
- На компьютере у всех горизонтальных рядов тонкая видимая полоса прокрутки, колесо мыши над рядом
  прокручивает его вбок (разделы склада, фильтры).
- Удалены неиспользуемые `d-cosmos.js`, `d-command.js`, `d-atlas.js`: сайт всегда работает в макете
  `g` (Bento + оформления), `DLIB` пуст.

## 139.4 Итог проверки

Автообход после исправлений: 0 экранов с замечаниями во всех шести оформлениях (светлая тема, телефон и
ноутбук, все роли), в тёмной теме (Bento, Dark Elegance), на маленьком телефоне и планшете. В казахском
остались только принятые заимствования и данные магазина. Сквозные сценарии: 21 из 21, ошибок JS нет.

## 139.5 Что осталось решить

- Помощник и флорист видят «Оплаты», «Чаты», «Клиенты» — так же, как оператор. Нужно решение владельца.
- Внутренний сбой Firestore «INTERNAL ASSERTION FAILED (ca9)» на стенде воспроизводился только на
  перегруженном эмуляторе. На чистом эмуляторе за полный прогон его не было. Защита
  (автоперезагрузка, записи через REST) остаётся.
